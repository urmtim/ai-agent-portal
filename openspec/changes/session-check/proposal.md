# Proposal

## Why

В Docker-копии портала (порт 3080) чат падал с «Failed to fetch the chat response»: сервер не мог сохранить чат, потому что пользователя из сессии нет в базе. Браузер делит cookie между портами одного хоста, поэтому вход в `npm run dev` (порт 3000, своя база) подсовывал 3080 чужую сессию. Та же дыра шире: сессия (JWT) не сверяется с базой, и удалённый или отключённый пользователь остаётся в системе до конца срока сессии, а смена роли не действует до перевхода.

## What Changes

- Сессия при каждом обращении сверяется с базой: пользователь должен существовать и быть активным; роль берётся из базы. Иначе сессия считается пустой — защищённые страницы ведут на вход, запросы к API отклоняются.
- Имя cookie сессии можно задать переменной `AUTH_SESSION_COOKIE`; Docker-копия получает своё имя, чтобы не мешать dev-серверу на том же хосте.
- **BREAKING:** нет (активные пользователи ничего не замечают).

### Modified Capabilities
- `user-admin`: новое требование — отключение, удаление и смена роли действуют на уже открытые сессии сразу.

## Impact

- `auth.ts` — проверка пользователя в колбэке `jwt`.
- `auth.config.ts` — имя cookie из окружения.
- `proxy.ts` — полный `auth` (proxy в Next 16 работает на Node.js), чтобы раздел «Админ» видел текущую роль.
- `docker-compose.yml` — `AUTH_SESSION_COOKIE`.
