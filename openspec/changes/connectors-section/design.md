## Context

Почтовые подключения живут в таблице `McpConnection` (kind `mail`, config JSON `{host, port, secure, user}`, пароль в `secretEnc`), агенты и Ассистент ссылаются на них через `mcpIds` / `mcpAccess`. Раздел `/mcp` показывает их таблицей, вкладка «API» — пустая заглушка (`ASSISTANT_APIS = {}`), раздел `/api-access` — «в разработке». Почта читается только по IMAP (`imapflow`). Макет: `mockups/portal-all-screens.html`, экраны `#connectors`, `#mcp`, `#agentwin`.

## Goals / Non-Goals

**Goals:** раздел «Коннекторы» с почтой (IMAP/POP3 + SMTP) и API; выключение; перенос данных без потерь; вкладка «Коннекторы» у агента и Ассистента; описание 200px во всех окнах.

**Non-Goals:** MCP-серверы (внешние и встроенный «Портал»), отправка писем агентами, инструменты для API-коннектора.

## Decisions

- **Таблица та же.** Prisma-модель переименовывается в `Connector` с `@@map("McpConnection")`: данные остаются на месте, `prisma db push` ничего не пересоздаёт. Новые поля: `description String @default("")`, `enabled Boolean @default(true)`.
- **Ссылки — в новом поле.** У `Agent` и `Assistant` новое `connectorIds String @default("[]")`. `fix-data` один раз переносит из `mcpIds` id существующих коннекторов в `connectorIds` и очищает `mcpIds` / `mcpAccess` (они остаются для будущих MCP-серверов). Повторный запуск ничего не меняет: переносится, только пока `connectorIds` пуст, а в `mcpIds` есть коннекторы. Колонки доступа у коннекторов нет: почта и так только читается.
- **Настройки почты** — JSON `{protocol, host, port, user, smtpHost, smtpPort}`. Старый `{host, port, secure, user}` читается как IMAP без SMTP. SSL по порту (993/995/465); у старых записей учитывается сохранённый `secure`, пока их не пересохранят. Пресеты сервисов (Mail.ru/Яндекс/Gmail) уходят из окна.
- **POP3 — свой клиент** `lib/pop3.ts` поверх `node:tls` / `node:net`: USER/PASS, STAT, TOP, RETR, QUIT, построчный разбор ответов, таймауты. Поиск: последние до 200 писем, заголовки через `TOP n 0`, фильтр по дате, отправителю и теме; совпавшие (до limit) читаются `TOP n 40` для начала текста. id письма — номер в ящике. `mailbox.ts` выбирает IMAP или POP3 по `protocol`, остальной код не знает разницы.
- **SMTP только проверяется:** `nodemailer.createTransport(...).verify()` тем же логином и паролем.
- **API-коннектор:** `{url}` + необязательный токен в `secretEnc`. Проверка — `GET url` с таймаутом 15 с.
- **Сохранение подключается** (как у моделей), если коннектор новый, изменились поля подключения или введён новый пароль; ошибка возвращается с полем: `{error, field}`. Статус после успешного сохранения — «подключено».
- **YAML коннектора** — `lib/connector-spec.ts` (чистые функции, тесты): `version, type, name, description, enabled` и поля подключения; пароль и токен не пишутся и не читаются (предупреждение).
- **YAML агента:** ключ `connectors:` (список названий). Старые `mcp:` (объекты с `name`) читаются как коннекторы, `api:` игнорируется.
- **Навигация:** ключ `api` → `connectors` (`/connectors`); `parsePins` заменяет сохранённый `api` на `connectors`. `/api-access` — `redirect("/connectors")`.
- **Окна:** `ConnectorModals.tsx` повторяет `ModelModals.tsx` (вкладки, ошибки под полем, `useUnsavedGuard`, `useModalHead` для ползунка, `QuestionModal` на загрузку YAML). Описание — `.field.grow.half` с высотой 200px в `globals.css`: так меняются сразу модель, агент и коннектор.

## Risks / Trade-offs

- [Номер письма POP3 меняется, если письма удаляют между поиском и чтением] → чтение идёт сразу после поиска в одном ответе модели; при несовпадении вернётся другое письмо или «такого письма нет». Приемлемо для личного ящика.
- [POP3 не знает «непрочитано»] → `unreadOnly` по POP3 игнорируется, все письма помечены прочитанными (`unread: false`).
- [Сохранение требует доступного сервера] → как у моделей; осознанно.
- [Запрос GET к адресу, который ввёл пользователь, идёт с сервера] → портал личный, адрес вводит сам владелец, так же устроены модели.

## Migration Plan

`prisma db push` (новые колонки с значениями по умолчанию) → `fix-data` переносит `mcpIds` → `connectorIds`. Откат: старый код читает `mcpIds`, которые очищены, — значит при откате нужно вернуть их из `connectorIds` вручную; данные почты не трогаются.
