# Design

## Context

- `components/Header.tsx` — серверный компонент: читает сессию (`auth()`), рисует логотип, шесть `NavLink` и `UserMenu`. `NavLink` — клиентский, подсвечивает по `usePathname()`.
- Шапка подключена в `app/(app)/layout.tsx`, поэтому на `/login` и `/invite` её уже нет — это требование выполняется само.
- Доступ к `/admin/*` уже ограничен в `auth.config.ts` (`authorized`), а все прочие адреса, кроме входа, закрыты `proxy.ts`. Новые `/chat`, `/mcp`, `/models` попадают под тот же matcher без правок.
- Эталон поведения и стилей — `mockups/portal-all-screens.html` (блоки `NAV`, `renderNav`, `dropSlot`, стили `.lbtn`, `.tray`, `.titem`, `nav.menu a.temp`). Токены цветов в `app/globals.css` совпадают с макетом (`--soft`, `--line`, `--primary-soft`, …).
- Тестового фреймворка в проекте нет; есть `tsx` в devDependencies.

## Goals / Non-Goals

**Goals:**
- Перенести навигацию макета 1:1 по поведению и виду.
- Отделить чистую логику меню (состав, порядок, разбор сохранённого) от React, чтобы её можно было проверить юнит-тестами без браузера.

**Non-Goals:**
- Хранение закреплений на сервере (между устройствами) — позже, если понадобится.
- Наполнение страниц Чат/MCP/Модели — отдельные изменения.
- Перенос домашней страницы `/` на чат — пока `/` остаётся «Обучение».
- Перетаскивание пальцем на телефоне (HTML5 drag-and-drop там не работает); на телефоне остаются трей и булавка.

## Decisions

1. **Каталог разделов — один модуль `lib/nav.ts`.**
   - Модуль описывает пункты: ключ, подпись, адрес, группу, признак «только админ», а также префиксы адресов для подсветки.
   - В нём же чистые функции:
     - `parsePins(raw, allowed)` — разбор сохранённого значения с откатом на умолчание;
     - `navKeyForPath(pathname)` — какой раздел подсвечивать;
     - `movePin(pins, key, index)`;
     - `unpin(pins, key)`.
   - Альтернатива — держать всё в компоненте. Отвергнута: такую логику не проверить без браузера.

2. **Шапка: серверная оболочка + клиентское меню.**
   - `Header` остаётся серверным: берёт сессию и передаёт в клиентский `AppNav` только `isAdmin`.
   - `AppNav` рисует кнопку 9 точек, меню и трей.
   - Подсветка строится на `usePathname()`, как в нынешнем `NavLink`. Сам `NavLink` удаляется.

3. **Сохранение — `localStorage`, ключ `portal.nav.pins.v1`.**
   - Номер версии в ключе позволяет сбросить настройки при смене каталога.
   - До гидрации рендерится меню по умолчанию, сохранённое применяется в `useEffect`. Возможное мигание на первом кадре принимаем ради простоты.
   - Альтернатива — cookie с серверным рендером. Отвергнута: пет-проект, лишняя сложность.

4. **Админские пункты фильтруются при рендере, а не при сохранении.**
   - Закрепления остаются в хранилище, но для не-админа не показываются.
   - Защита самих страниц остаётся в `auth.config.ts`.

5. **Drag-and-drop — нативный HTML5, как в макете.**
   - Позиция вставки считается по серединам соседних пунктов, без перетаскиваемого.
   - Маркер вставки — классы `ins-l` / `ins-r`.
   - Новых зависимостей нет. dnd-kit отвергнут как избыточный для одного ряда.

6. **Стили — перенос блоков из макета в `app/globals.css`.**
   - Сетка шапки `1fr | центр | 1fr`, правила `.lbtn`, `.tray`, `.titem`, `.temp` и `.pin`.
   - Мобильное правило `max-width: 680px` скрывает имя пользователя.
   - Старые `.brand` / `.logo` удаляются, если больше нигде не используются.

7. **Заглушки страниц.** `app/(app)/chat|mcp|models/page.tsx` вызывают `requireUser()` и показывают `pagehead` с заголовком и строкой «Раздел в разработке».

## Risks / Trade-offs

- [Мигание меню при загрузке, если сохранён нестандартный порядок] → Принимаем. Рендер скрыт до применения настроек только у списка пунктов, сама шапка видна сразу.
- [Нет drag-and-drop на сенсорных экранах] → Закрепление доступно булавкой. Открепление на телефоне пока недоступно — зафиксировано в Non-Goals.
- [Старые закрепления ссылаются на удалённые ключи] → `parsePins` отбрасывает неизвестные ключи. Если ничего не осталось, возвращается меню по умолчанию.
