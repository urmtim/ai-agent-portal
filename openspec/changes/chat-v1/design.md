# Design

## Context

- Модели уже в реестре (`LlmModel`), выбор модели: `resolveModel(modelId)` → `endpointFor()` в `lib/llm.ts`. Агенты запускаются через `runAgent(agentId)` в `lib/agents/runner.ts`, прогон пишется в `AgentRun`.
- Свой LLM-клиент (`lib/llm.ts`) умеет только разовый ответ без потока и без инструментов. Писать поток, вызовы инструментов и подтверждения руками долго, поэтому берём Vercel AI SDK 7 (`ai`, `@ai-sdk/react`, `@ai-sdk/openai-compatible`): он работает с любым OpenAI-совместимым адресом (ollama.com, Ollama, GLM) и даёт `useChat`, поток, остановку, повтор, инструменты и подтверждение (`toolApproval`).
- Макет экрана: `mockups/portal-all-screens.html`, экран `chat` (классы `.cwrap`, `.hist`, `.cmain`, `.cthread`, `.cu`, `.ca`, `.cstep`, `.hitl`, `.ccomp`).
- Next.js 16, `proxy.ts` уже требует сессию для всех путей, кроме `/api/auth`.

## Goals / Non-Goals

**Goals:** сохранённые чаты с историей, выбор модели, поток с остановкой, копировать/повторить/изменить, два инструмента («Траты», «Запустить агента») с подтверждением запуска.

**Non-Goals:** шаблоны по `/`, память, подсказки, временный чат, голос, вложения, поиск по тексту сообщений, диспетчер среди многих агентов, MCP, общий доступ к чатам.

## Decisions

### Хранение: один JSON на чат
`Chat { id, ownerId, title, modelId?, pinned, archived, messages (JSON UIMessage[]), createdAt, updatedAt }`. Сообщения — массив `UIMessage` AI SDK одной строкой, как в документации SDK. Отдельная таблица сообщений не нужна: чат читается и пишется целиком, поиск — только по названию.

Альтернатива — таблица `ChatMessage`. Отклонена: правка и повтор переписывают хвост истории, проще перезаписать массив.

### Клиент шлёт всю историю, сервер перезаписывает чат
`useChat` по умолчанию отправляет все сообщения. Сервер проверяет их `validateUIMessages` с нашими инструментами, сохраняет сразу (чтобы не потерять сообщение пользователя при ошибке модели) и ещё раз в `onEnd` с ответом. Так «Изменить» и «Повторить» работают на клиенте средствами SDK (`setMessages` + `sendMessage`, `regenerate`), а сервер просто сохраняет присланное.

Клиент может подменить историю своего чата — это его же данные. Подделать подтверждение запуска он не может: `experimental_toolApprovalSecret` (HMAC от `AUTH_SECRET`) подписывает запросы подтверждения, сервер отклоняет неподписанные.

### Id чата создаёт клиент
Новый чат получает id в браузере (`generateId` SDK). Первый запрос создаёт строку `Chat` с этим id и владельцем; если id занят чужим чатом — 404. После первого ответа клиент меняет адрес на `/chat/<id>` через `history.replaceState` и обновляет историю (`router.refresh()`), без перезагрузки ленты.

### Модель для AI SDK
`lib/chat/model.ts`: `chatModel(modelId)` → `resolveModel` + `endpointFor` → `createOpenAICompatible({ baseURL, name: "portal", apiKey }).chatModel(model)`. Если чат указывает удалённую модель, `pickModel` уже откатывается на модель по умолчанию.

### Инструменты
`lib/chat/tools.ts` собирает инструменты для конкретного пользователя:
- `get_spending({ days })` — агрегирует `Receipt` владельца: итог, число чеков, категории, топ-5 магазинов.
- `run_agent({ agentId })` — только если у пользователя есть включённые агенты; `agentId` — `z.enum` из их id, описание инструмента перечисляет агентов с описаниями типов. `execute` вызывает `runAgent`, затем читает прогон и возвращает `{ status, summary, processed, created, log }` (журнал обрезан).

`toolApproval: { run_agent: "user-approval" }`, `stopWhen: isStepCount(5)`.

### Название чата
Отдельный server action `ensureChatTitle(chatId)`: клиент вызывает его после первого завершённого ответа. Он спрашивает модель (`generateText`, до 6 слов, без кавычек) и при неудаче берёт начало первого сообщения (`fallbackTitle`, чистая функция с тестом). Так генерация названия не задерживает поток ответа.

### Ошибки
`toUIMessageStream({ onError })` возвращает текст ошибки, из которого вырезан токен модели. Нет модели — сервер отвечает 400 с текстом, а страница заранее показывает предупреждение и блокирует отправку.

### Экран
- `app/(app)/chat/page.tsx` (новый чат) и `app/(app)/chat/[id]/page.tsx` (сохранённый) — серверные: читают список чатов пользователя и модели, рендерят `ChatScreen`.
- `ChatScreen` (клиент): панель истории (`ChatHistory`) и ленту (`ChatThread`). `useChat({ id, messages, transport })`, тело запроса дополняется `modelId`. Компонент пересоздаётся по `key = chatId`.
- Группировка истории — чистая функция `groupChats(chats, now)` с тестами.
- Ответ ассистента — `react-markdown` + `remark-gfm` (уже в зависимостях).
- Части сообщения: текст → `.ca`; вызов инструмента → `.cstep` (сводка + `<pre>` подробностей); `approval-requested` → `.hitl`; ошибка → `.ca` с классом ошибки.

## Risks / Trade-offs

- [Модель не умеет вызывать инструменты] → ответ придёт с ошибкой сервера модели; в ленте видна ошибка. Выбор другой модели в шапке решает это.
- [AI SDK 7 — новая версия, API отличается от привычного] → сверяемся с документацией в `node_modules/ai/docs`.
- [Остановка обрывает поток, `onEnd` может не сработать] → сообщение пользователя уже сохранено в начале запроса; недописанный ответ сохранится при следующей отправке, потому что клиент шлёт всю историю.
- [Большие чаты] → JSON целиком на каждую отправку; для семейного портала приемлемо.

## Migration Plan

`prisma db push` добавляет таблицу `Chat`, существующие данные не трогает. Docker-копия догоняет схему сама при `npm run deploy`. Откат — удалить таблицу, остальное не зависит от неё.
