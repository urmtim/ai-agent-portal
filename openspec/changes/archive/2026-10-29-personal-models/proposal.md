# Proposal

## Why

Подключения MCP, чаты, агенты и ассистент уже личные, а реестр моделей общий: им управляет администратор, и все пользуются его моделями и токенами. Пользователь хочет разделения: каждый видит и использует свои модели.

## What Changes

- У каждой модели есть владелец. Страница «Модели» показывает только свои модели; добавлять, менять, проверять и удалять их может любой пользователь — свои.
- Модель по умолчанию — своя у каждого. Первая своя модель становится моделью по умолчанию.
- Агенты, ассистент и чат выбирают только из моделей своего владельца; чужую модель сервер не примет.
- Существующие модели (общие) передаются администратору — первому по дате создания; это делается при старте портала один раз.
- В выборе модели у ассистента и агента нет пункта «По умолчанию — …», дублирующего саму модель: список — только модели, и пока ничего не выбрано, в нём стоит модель по умолчанию; сохраняется выбранная модель.
- Модель из `.env` (`LLM_*`) остаётся запасной для всех, у кого своих моделей нет.
- **BREAKING:** пользователи без своих моделей больше не пользуются моделями администратора (кроме запасной из `.env`).

### Modified Capabilities
- `llm-models`: модели личные; кто управляет; порядок выбора модели в пределах владельца.
- `assistant-settings`: выбор модели без пункта «По умолчанию».

## Impact

- Prisma: `LlmModel.ownerId` (+ связь с пользователем), `prisma db push`; `prisma/fix-data.ts` — передать модели без владельца администратору (идемпотентно), вызывается в `docker/start.sh`.
- `lib/llm.ts` (выбор модели по владельцу), `lib/chat/model.ts`, `lib/agents/receipts.ts`, `lib/assistant.ts`.
- `app/(app)/models/` (страница и действия без ограничения «только админ», с проверкой владельца), `app/(app)/agents/`, `app/(app)/chat/`, `app/api/chat/route.ts`.
