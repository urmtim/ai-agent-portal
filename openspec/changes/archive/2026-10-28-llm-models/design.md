# Design

## Context

- `lib/llm.ts` — минимальный OpenAI-совместимый клиент. Модель берётся только из `process.env.LLM_*`. Вызывается из `lib/agents/receipts.ts` (`llmJson`).
- Общие таблица, модалка и тост уже есть (`components/ui/*`, спека `list-pages`). Вкладки AI и заглушка `/models` тоже есть.
- `AUTH_SECRET` задан всегда (без него не работает вход). SQLite, `prisma db push` без миграций.

## Goals / Non-Goals

**Goals:**
- Реестр моделей с безопасным хранением токена и обратной совместимостью с `.env`.
- Чистая логика выбора модели и шифрования покрыта юнит-тестами.

**Non-Goals:**
- Запрос списка моделей у сервера (`GET /models`) и выпадающий выбор модели — пока ввод вручную.
- Учёт расходов и токенов, лимиты.
- Модели для чата и конструктора — они просто будут вызывать тот же выбор модели.

## Decisions

1. **Схема.**
   - Модель `LlmModel`:
     - `id`, `name`, `baseUrl`, `model`;
     - `tokenEnc String?`, `isDefault Boolean`;
     - `checkedAt DateTime?`, `checkOk Boolean?`, `checkMsg String`;
     - `createdAt`.
   - `Agent.modelId String?` со связью `onDelete: SetNull`.
   - Признак «по умолчанию» поддерживается в транзакции: при установке у одной модели сбрасывается у остальных. Уникального индекса в SQLite на «ровно одна true» нет — инвариант держим кодом.

2. **Шифрование — `lib/secret.ts`.**
   - AES-256-GCM, ключ — `sha256("llm-token:" + AUTH_SECRET)`, формат `v1:<iv>:<tag>:<data>` в base64url.
   - Если расшифровать не удалось (сменился `AUTH_SECRET`), вызов LLM падает с ошибкой «Токен модели не читается — введите его заново». Альтернатива — хранить токен в `.env` по имени переменной; отвергнута: в макете токен вводится в модалке, и переменная на каждую модель неудобна.

3. **Выбор модели — `resolveModel(agentModelId?)` в `lib/llm.ts`.**
   - Порядок: модель агента → модель по умолчанию → `.env` → ошибка.
   - Решающая чистая функция `pickModel(candidates)` вынесена отдельно и тестируется без базы.
   - `llmChat` / `llmJson` получают необязательный `modelId`. `runReceiptsAgent` передаёт `agent.modelId`.

4. **Проверка подключения — `pingModel({ baseUrl, model, token })`.**
   - `POST {baseUrl}/chat/completions` с сообщением «ping» и `max_tokens: 1`, таймаут 20 с через `AbortSignal.timeout`.
   - Возвращает `{ ok, ms, message }`. Текст ошибки обрезается до 200 символов, токен в него не попадает.
   - Проверка в модалке использует введённые данные. Если поле токена пустое при правке, берётся сохранённый токен (по `id`).

5. **Server actions в `app/(app)/models/actions.ts`.**
   - Все вызывают `requireAdmin()`.
   - Формы валидируются через zod (адрес — `^https?://`).
   - Отдают клиенту только `{ id, name, baseUrl, model, isDefault, hasToken, status }`. `tokenEnc` за пределы сервера не уходит.

6. **UI** — `ListTable` + `Modal` из `components/ui`, разметка модалки по макету. Поле «Токен» — `type=password` с кнопкой показа. Колонка «Агенты» считается на сервере: агенты с этой моделью, плюс у модели по умолчанию — агенты без своей модели.

## Risks / Trade-offs

- [Смена `AUTH_SECRET` делает токены нечитаемыми] → Понятная ошибка при вызове и в статусе проверки. Токен вводится заново.
- [SSRF через «Проверить»: сервер ходит на произвольный адрес] → Только администратор. Ответ сервера наружу не отдаётся, кроме кода и короткого текста ошибки.
- [Инвариант «одна модель по умолчанию» держится кодом] → Все изменения идут в `prisma.$transaction`. При чтении, если по умолчанию ни одна, берётся самая ранняя.

## Migration Plan

- `npx prisma db push` добавляет таблицу и колонку. Данные не мигрируются: при пустом реестре работает `.env`.
- Откат: удалить таблицу и колонку — агенты вернутся к `.env`.
