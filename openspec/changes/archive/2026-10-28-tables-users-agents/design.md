# Design

## Context

- Страницы — серверные компоненты: читают Prisma и вызывают server actions (`app/(app)/admin/actions.ts`, `app/(app)/agents/actions.ts`). Клиентский код уже есть: `CreateUserForm` с `useActionState`.
- Защита: `requireAdmin()` / `requireUser()` в `lib/session.ts`, плюс `/admin/*` закрыт в `auth.config.ts`. Вход разрешён только при статусе `ACTIVE` (`auth.ts`).
- Почта: `lib/mail.ts`, транспорт `MAIL_TRANSPORT` (по умолчанию `console` — письмо пишется в лог сервера).
- В `app/globals.css` уже есть `table`/`th`/`td`, `.st.*`, поля, `.formerr`. Нет `.tbar`, `.search`, `.ibtn`, `.mbg`/`.modal`, `.tabs`, тоста — их стили берём из макета.

## Goals / Non-Goals

**Goals:**
- Общие клиентские примитивы, которые переиспользуют MCP и Модели: таблица с поиском и фильтром, модалка, тост, иконки.
- Проверки «нельзя потерять последнего администратора» вынести в чистую функцию с юнит-тестами.

**Non-Goals:**
- Серверная пагинация и сортировка (членов семьи и агентов единицы).
- Колонка ID из базы: идентификаторы — cuid, показываем порядковый номер.
- Конструктор агентов — отдельное изменение. «Настроить» пока ведёт на существующую страницу агента.

## Decisions

1. **`components/ui/ListTable.tsx` — клиентская таблица с фильтрацией в браузере.**
   - Сервер передаёт строки: `key`, ячейки (`ReactNode[]`, в том числе клиентские компоненты действий), `search` (текст для поиска), `facets` (значения для фильтра), `className`.
   - Колонки и описание фильтров передаются отдельно.
   - Почему не серверный поиск по `searchParams`: данных мало, а мгновенный отклик без перезагрузки — как в макете.

2. **`components/ui/Modal.tsx`** — разметка `.mbg > .modal[role=dialog][aria-modal]` из макета.
   - Esc, клик по фону, крестик; фокус в первое поле при открытии.
   - Не `<dialog>`: нужен тот же вид и поведение, что в макете, без сюрпризов с `::backdrop` и формами.

3. **`components/ui/Toast.tsx`** — провайдер в `app/(app)/layout.tsx` и хук `useToast()`. Одно сообщение за раз, 2 секунды.

4. **Формы в модалках — `useActionState` + server action, возвращающий `{ error } | { ok }`.**
   - Модалка закрывается и показывает тост только при `ok`.
   - Ссылку-приглашение action возвращает только при `MAIL_TRANSPORT=console`, чтобы в бою она не утекала в браузер.

5. **Проверки администратора — `lib/user-guard.ts`.**
   - Функция `checkUserChange({ actorId, target, next, activeAdminCount })` возвращает текст ошибки или `null`.
   - Её вызывают `updateUser` и `deleteUser`; тесты в `lib/user-guard.test.ts`.

6. **Статус при включении входа.** Если у пользователя нет `passwordHash`, статус «приглашён», иначе «активен». Так включение отключённого приглашённого не делает его активным без пароля.

7. **Модель в таблице агентов** — `process.env.LLM_MODEL` или «не задана». Реестр моделей появится в изменении про «Модели». Колонка MCP выводится из типа агента: `RECEIPTS` → «Почта».

8. **Запуск агента из строки** — клиентская кнопка вызывает `runAgentNow`. Action возвращает итог прогона для тоста. Пока идёт `useTransition`, кнопка неактивна.

9. **Иконки** — SVG из макета, собранные в `components/ui/icons.tsx`. Иконочные кнопки — `IconButton` с `title` и `aria-label`.

## Risks / Trade-offs

- [Фильтрация в браузере не масштабируется] → Сотни строк здесь не ожидаются. `ListTable` можно позже переключить на серверный режим.
- [Удаление пользователя каскадно стирает его данные] → Подтверждение называет пользователя и предупреждает, что агенты, чеки и прогресс тоже удалятся.
- [Долгий прогон агента блокирует server action] → Прогон «Чеков» ограничен `max` писем. Фоновые прогоны — позже.
