## Context

Почтовый коннектор (`Connector`, kind `mail`) хранит IMAP или POP3, необязательный SMTP, логин и зашифрованный пароль. Инструменты `mail_search`, `mail_read`, `mail_count` (`lib/chat/mail-tools.ts`) работают только с «Входящими» и получают их Ассистент (`lib/chat/tools.ts`) и «Свой агент» (`lib/agents/custom.ts`) по первому включённому почтовому коннектору. В чате подтверждение есть только у запуска агента: AI SDK `toolApproval` с подписанным секретом.

## Goals / Non-Goals

**Goals:**
- Полный набор действий над ящиком, которые дают IMAP и SMTP, по умолчанию включён; пользователь снимает лишнее галочками.
- Группы по последствиям: чтение, изменение (обратимое), отправка (наружу).
- Чего не позволяет подключение, то не предлагается модели и серое в окне.
- Подтверждение изменений и отправки в чате по HITL Ассистента.

**Non-Goals:**
- Сохранять вложения файлом: некуда, раздела «Документы» нет.
- Удалять письма насовсем, удалять папки.
- Права на уровне агента: галочки только у коннектора.
- Копия отправленного в «Отправленные»: Mail.ru, Яндекс и Gmail кладут её сами.

## Decisions

**Каталог (`lib/mail-catalog.ts`, без сервера, с тестами).** Ключ галочки → инструмент модели, название, описание, группа `read | change | send`, что нужно (`imap` | `smtp`):

| Ключ | Инструмент | Нужно |
|---|---|---|
| search, read, attach, count | mail_search, mail_read, mail_attachment, mail_count | — |
| folders | mail_folders | imap |
| move, flags, spam, drafts, folder_new, trash | mail_move, mail_mark, mail_spam, mail_draft, mail_folder, mail_trash | imap |
| send, reply, forward | mail_send, mail_reply, mail_forward | smtp |

`availableMailTools(cfg, toolsOff)` → имена инструментов модели. `mailApproval(group, hitl)`: изменение спрашивают при `changes_and_send`, отправку — при `changes_and_send` и `send_only`.

**Хранение — `Connector.toolsOff`** (JSON-список ключей, по умолчанию `[]`). Храним выключенное, чтобы новые инструменты были включены у всех. В YAML коннектора — `tools:` со списком включённых ключей. Если `tools:` нет, галочки не меняются.

**Папки.** `mail_folders` отдаёт папки с путём, русским названием для особых (`\Inbox`, `\Sent`, `\Drafts`, `\Trash`, `\Junk`, `\Archive` → «Входящие», «Отправленные», «Черновики», «Корзина», «Спам», «Архив»), числом писем и непрочитанных. Остальные инструменты принимают `folder` (путь или название, без учёта регистра, по умолчанию «Входящие») и разбирают его чистой функцией `resolveFolder`. Особую папку ищем по флагу special-use, затем по обычным именам (Trash, Корзина, Deleted…). «Корзину», «Спам» и «Черновики» создаём, если их нет. id письма — его IMAP uid в этой папке.

**POP3.** У POP3 одна папка. `folder` кроме «Входящих» даёт ошибку «По POP3 есть только «Входящие»». Инструменты из колонки «Нужно» модели не предлагаются.

**Изменения.** Перемещение — `messageMove` (imapflow сам делает COPY + EXPUNGE, если у сервера нет MOVE). Отметки — флаги `\Seen` и `\Flagged`. Спам — перемещение в «Спам» или обратно во «Входящие». Корзина — перемещение в «Корзину»; письмо, уже лежащее в корзине, не трогаем. Черновик собирается nodemailer `MailComposer` и кладётся APPEND в «Черновики» с флагом `\Draft`. Если черновик отвечает на письмо, у него ставятся `In-Reply-To` и `References`.

**Отправка.** nodemailer по SMTP коннектора, от его логина. Ответ: адресат — `Reply-To` или отправитель исходного письма, «всем» добавляет получателей без своего адреса, тема «Re: », цитата исходного текста. Пересылка: тема «Fwd: », исходный текст и все вложения.

**Вложения.** `mail_read` перечисляет вложения с номерами, именами и размером. `mail_attachment` отдаёт текст по номеру: PDF и Word через `extractDocText`, текст, Markdown, CSV и HTML. Другие виды — ошибка «Этот вид вложения пока не читается». Текст не длиннее 20 000 знаков.

**Подтверждение в чате.** `toolApproval` для почтовых инструментов изменения и отправки по `cfg.hitl` Ассистента. Карточка общая для всех таких инструментов: «⏸ Нужно подтверждение», что именно будет сделано (кому, тема, сколько писем, куда), «Выполнить» и «Отмена». Отказ пишется в журнал. Агенты своих действий не подтверждают: их запуск уже подтверждён по их HITL.

**Модель.** Инструменты описаны по-русски. В `access.connectors[].gives` — что умеет коннектор словами по включённым группам. В инструкции сказано: менять и отправлять письма — только по просьбе пользователя или задаче агента.

## Risks / Trade-offs

- **Пароль приложения только на чтение.** Изменения по IMAP могут быть отклонены уже при работе. Ошибка уходит словами: «Почта не дала изменить письмо: проверьте права пароля приложения».
- **Полные права по умолчанию.** Изменение обратимо, отправка в чате подтверждается при HITL по умолчанию, удаления насовсем нет.
- **14 инструментов в контексте модели.** Описания короткие, модель получает только включённые.
- **GreenMail в e2e.** Особые папки он не создаёт: их создание и проверяет e2e.
