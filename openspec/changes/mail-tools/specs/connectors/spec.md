## MODIFIED Requirements

### Requirement: Окно коннектора
«Добавить» и «Изменить» SHALL открывать окно того же размера, что окна модели и агента. В шапке — «Новый коннектор» или название, ползунок без подписи (подсказка «Коннектор включён» / «Коннектор выключен») и ×. Вкладки «Общее · Подключение · Инструменты · YAML»:
- «Общее»: Название*, Описание (200px высотой);
- «Подключение»: первым — Тип*, под ним поля выбранного типа. У нового коннектора тип сначала не выбран («Выберите тип», серым): других полей нет, пока тип не выбран. При смене типа поля меняются сразу; у сохранённого коннектора тип не меняется;
- «Инструменты»: только у почты (см. `mail-tools`);
- «YAML»: всё, кроме паролей и токенов, текстом с подсветкой; правка YAML заполняет другие вкладки; «Скачать» и «Загрузить» без цвета, «Загрузить» сначала спрашивает «Загрузить YAML?».

Внизу — только «Сохранить»; без типа «Сохранить» и «Проверить» говорят «Выберите тип» под полем. При правке «Сохранить» неактивна, пока ничего не изменено; × и Esc при изменениях спрашивают «Закрыть без сохранения?».

#### Scenario: Тип не выбран
- **WHEN** пользователь нажимает «Добавить»
- **THEN** на вкладке «Подключение» только поле «Тип» с «Выберите тип», вкладки «Инструменты» нет

#### Scenario: Смена типа
- **WHEN** в новом коннекторе пользователь выбирает тип «API»
- **THEN** под полем «Тип» появляются «Адрес API» и «Токен», вкладки «Инструменты» нет, название остаётся

#### Scenario: Тип не меняется
- **WHEN** пользователь открывает сохранённый коннектор
- **THEN** поле «Тип» видно, но недоступно

#### Scenario: Ничего не меняли
- **WHEN** пользователь открывает коннектор и ничего не меняет
- **THEN** «Сохранить» неактивна, × закрывает окно без вопроса

### Requirement: Коннектор «Почта»
Поля почты:
- Получение — IMAP или POP3;
- Сервер входящей почты* и Порт* (993 для IMAP, 995 для POP3 по умолчанию; при смене протокола порт меняется, `imap.…` в адресе меняется на `pop.…` и обратно);
- Отправка — «Нет» (по умолчанию; хватает пароля приложения только на чтение) или «SMTP»: тогда Сервер исходящей почты* и Порт* (465 по умолчанию); при «Нет» эти поля серые, не проверяются и не сохраняются, в YAML — `outgoing: none`;
- Логин* и Пароль приложения*; поясняющих подсказок под полями нет.

SSL SHALL включаться по порту: 993, 995 и 465 — SSL, остальные — без него. Пароль MUST храниться зашифрованным и MUST NOT отдаваться в браузер, писаться в журнал, YAML или показываться; пустое поле при правке SHALL оставлять прежний пароль.

Агентам и Ассистенту почта даёт инструменты, включённые на вкладке «Инструменты» (см. `mail-tools`). Чтение MUST NOT помечать письма прочитанными. По POP3 поиск идёт по последним письмам ящика (до 200), отметки «непрочитано» нет.

#### Scenario: Пароль только на чтение
- **WHEN** пользователь оставляет «Отправка — Нет» и сохраняет почту с паролем приложения только на чтение
- **THEN** проверка идёт только по входящей почте, коннектор сохраняется; поля SMTP серые

#### Scenario: Отправка не пускает
- **WHEN** выбрано «SMTP», входящая почта пускает, а SMTP отказывает в пароле
- **THEN** рядом с «Проверить» видно «✕ Отправка: Неверный логин или пароль приложения», подсвечен сервер исходящей почты

#### Scenario: POP3
- **WHEN** пользователь выбирает «POP3» при сервере `imap.mail.ru` и порте 993
- **THEN** сервер становится `pop.mail.ru`, порт — 995

#### Scenario: Почта по POP3 в чате
- **WHEN** Ассистенту добавлена почта по POP3 и пользователь спрашивает, что пришло за неделю
- **THEN** Ассистент находит письма за неделю и может открыть письмо целиком

#### Scenario: Правка без пароля
- **WHEN** пользователь меняет название почтового коннектора, не трогая пароль
- **THEN** прежний пароль сохраняется и коннектор работает

#### Scenario: Письмо остаётся непрочитанным
- **WHEN** Ассистент открывает непрочитанное письмо по IMAP
- **THEN** в почтовом ящике письмо остаётся непрочитанным
