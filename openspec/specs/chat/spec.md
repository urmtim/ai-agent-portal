# chat Specification

## Purpose
Чат с ассистентом портала: сохранённые чаты пользователя, потоковые ответы выбранной модели и инструменты, через которые ассистент читает данные портала и запускает агентов с подтверждением пользователя.

## Requirements

### Requirement: Хранение чатов
Система SHALL хранить чаты пользователя: название, модель, признаки «закреплён» и «в архиве», сообщения и время последнего изменения. Чат MUST быть доступен только своему владельцу: чужой чат на странице и в API ведёт себя как несуществующий.

#### Scenario: Первый ответ создаёт чат
- **WHEN** пользователь на `/chat` отправляет первое сообщение
- **THEN** создаётся чат со всеми сообщениями, адрес страницы меняется на `/chat/<id>`, чат появляется в истории

#### Scenario: Чужой чат
- **WHEN** пользователь открывает `/chat/<id>` чата другого пользователя или отправляет в него сообщение через API
- **THEN** страница отвечает «не найдено», API отвечает 404, чат не меняется

#### Scenario: Без входа
- **WHEN** запрос к API чата приходит без сессии
- **THEN** ответ не содержит данных и ничего не сохраняется

### Requirement: История чатов
Боковая панель SHALL показывать чаты пользователя, новые сверху, в группах «Закреплённые», «Сегодня», «Вчера», по дате для последней недели, «Ранее» и свёрнутой «Архив». Пустые группы MUST не показываться. Панель SHALL содержать «+ Новый чат», поиск по названиям и для каждого чата действия «Закрепить»/«Открепить», «В архив»/«Из архива», «Удалить» (с подтверждением). На узком экране панель SHALL открываться кнопкой поверх ленты, на широком — скрываться этой же кнопкой.

#### Scenario: Поиск
- **WHEN** пользователь вводит часть названия в поиск
- **THEN** остаются только подходящие чаты, группы без совпадений скрываются

#### Scenario: Закрепление
- **WHEN** пользователь закрепляет чат
- **THEN** чат переходит в группу «Закреплённые» вверху списка

#### Scenario: Архив
- **WHEN** пользователь отправляет чат в архив
- **THEN** чат пропадает из обычных групп и виден только в группе «Архив»

#### Scenario: Удаление открытого чата
- **WHEN** пользователь подтверждает удаление чата, который сейчас открыт
- **THEN** чат удаляется и открывается новый пустой чат

### Requirement: Название чата
После первого ответа ассистента система SHALL дать чату короткое название, сгенерированное моделью. Если модель не ответила, ответила пусто или слишком длинно, название MUST браться из начала первого сообщения пользователя (не длиннее 60 символов).

#### Scenario: Модель придумала название
- **WHEN** завершился первый ответ в новом чате и модель вернула название
- **THEN** чат в истории показывается под этим названием

#### Scenario: Модель недоступна
- **WHEN** запрос названия к модели завершился ошибкой
- **THEN** названием становится начало первого сообщения пользователя

### Requirement: Выбор модели
Шапка чата SHALL содержать выбор модели из реестра «Модели»; по умолчанию выбрана модель базового ассистента, а если она не задана — модель по умолчанию из реестра. Выбор MUST сохраняться в чате и применяться к следующим ответам. Если реестр пуст, а модель задана в `.env`, чат SHALL работать на ней без выбора. Если модели нет нигде, чат SHALL показывать предупреждение со ссылкой на «Модели», а отправка MUST быть недоступна.

#### Scenario: Смена модели
- **WHEN** пользователь выбирает в чате другую модель и отправляет сообщение
- **THEN** ответ генерирует выбранная модель, а при повторном открытии чата выбрана она же

#### Scenario: Модель удалили
- **WHEN** модель чата удалена из реестра
- **THEN** чат отвечает моделью по умолчанию

#### Scenario: Нет ни одной модели
- **WHEN** в реестре нет моделей и в `.env` модель не задана
- **THEN** вместо ответа видно предупреждение со ссылкой на «Модели», кнопка отправки неактивна

### Requirement: Потоковый ответ
Ответ ассистента SHALL появляться по мере генерации. Пока ответ идёт, кнопка отправки MUST превращаться в «Остановить»; остановка прерывает генерацию и оставляет уже полученный текст. Ошибка модели SHALL показываться в ленте понятным текстом, в котором нет токена модели. Enter SHALL отправлять сообщение, Shift+Enter — переносить строку.

#### Scenario: Остановка
- **WHEN** пользователь нажимает «Остановить» во время ответа
- **THEN** генерация прекращается, полученная часть ответа остаётся, поле ввода снова доступно

#### Scenario: Ошибка модели
- **WHEN** сервер модели отвечает ошибкой
- **THEN** в ленте видно сообщение об ошибке и кнопка «Повторить», введённое сообщение не теряется

### Requirement: Действия над сообщениями
Под ответом ассистента SHALL быть «Копировать», а под последним ответом — ещё «Повторить». Под сообщением пользователя SHALL быть «Копировать» и «Изменить». «Изменить» MUST открывать правку текста на месте; сохранение отбрасывает все сообщения после изменённого и отправляет его заново.

#### Scenario: Повторить
- **WHEN** пользователь нажимает «Повторить» под последним ответом
- **THEN** последний ответ заменяется новым, история сохраняется уже с ним

#### Scenario: Изменить
- **WHEN** пользователь правит своё сообщение из середины чата и сохраняет
- **THEN** сообщения после него удаляются, ассистент отвечает на исправленный текст

#### Scenario: Копировать
- **WHEN** пользователь нажимает «Копировать»
- **THEN** текст сообщения попадает в буфер обмена и появляется уведомление «Скопировано»

### Requirement: Инструменты ассистента
Ассистент SHALL иметь только инструменты, разрешённые в его настройках:
- «Траты» (API «Траты») — итог, число чеков, разбивка по категориям и крупнейшие магазины по тратам пользователя за последние N дней (1–365); только чтение, без подтверждения;
- «Запустить агента» — запуск одного из разрешённых и включённых агентов пользователя.

Инструменты MUST работать только с данными текущего пользователя. Каждый вызов SHALL отображаться в ленте строкой-сводкой, которая раскрывается в подробности (параметры и результат или журнал прогона).

#### Scenario: Вопрос о тратах
- **WHEN** API «Траты» разрешено и пользователь спрашивает, сколько потрачено за месяц
- **THEN** в ленте появляется строка вызова «Траты», а ответ ассистента опирается на её результат

#### Scenario: Нет агентов
- **WHEN** у пользователя нет разрешённых включённых агентов
- **THEN** инструмент «Запустить агента» ассистенту не предлагается

#### Scenario: Траты не разрешены
- **WHEN** API «Траты» не разрешено и пользователь спрашивает о тратах
- **THEN** инструмент не вызывается, ассистент говорит, что доступ к тратам не разрешён в настройках ассистента

### Requirement: Подтверждение действий
Запуск агента SHALL выполняться только после подтверждения пользователя: в ленте появляется карточка «⏸ Нужно подтверждение» с названием агента и кнопками «Запустить» и «Отмена». Подтверждение MUST проверяться на сервере, подделанное клиентом подтверждение не запускает агента. После прогона в ленте SHALL быть итог прогона и, если появились новые чеки, кнопка «Открыть «Траты»».

#### Scenario: Подтверждение
- **WHEN** ассистент хочет запустить агента и пользователь нажимает «Запустить»
- **THEN** агент выполняется, прогон записывается в его историю, ассистент сообщает итог

#### Scenario: Отказ
- **WHEN** пользователь нажимает «Отмена»
- **THEN** агент не запускается, в ленте видно «Запуск отменён», ассистент продолжает без него

#### Scenario: Ошибка прогона
- **WHEN** прогон агента завершился ошибкой (например, не настроена почта)
- **THEN** строка вызова показывает ошибку и журнал, ассистент объясняет, чего не хватает

### Requirement: Вход ведёт в последний чат
После входа система SHALL открывать последний изменённый чат пользователя, не считая архивных. Если таких чатов нет, MUST открываться новый чат.

#### Scenario: Есть чаты
- **WHEN** пользователь с несколькими чатами входит в портал
- **THEN** открывается `/chat/<id>` чата, в котором было последнее сообщение

#### Scenario: Последний чат в архиве
- **WHEN** самый свежий чат пользователя отправлен в архив
- **THEN** открывается самый свежий из неархивных чатов

#### Scenario: Чатов нет
- **WHEN** у пользователя ещё нет чатов
- **THEN** открывается новый чат «Чем помочь?»
