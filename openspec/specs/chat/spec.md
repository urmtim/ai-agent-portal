# chat Specification

## Purpose
Чат с ассистентом портала: сохранённые чаты пользователя, потоковые ответы выбранной модели и инструменты, через которые ассистент читает данные портала и запускает агентов с подтверждением пользователя.

## Requirements

### Requirement: Хранение чатов
Система SHALL хранить чаты пользователя: название, модель, признаки «закреплён» и «в архиве», сообщения и время последнего изменения. Чат MUST быть доступен только своему владельцу: чужой чат на странице и в API ведёт себя как несуществующий.

#### Scenario: Первый ответ создаёт чат
- **WHEN** пользователь на `/chat` отправляет первое сообщение
- **THEN** создаётся чат со всеми сообщениями, адрес страницы меняется на `/chat/<id>`, чат появляется в истории

#### Scenario: Чужой чат
- **WHEN** пользователь открывает `/chat/<id>` чата другого пользователя или отправляет в него сообщение через API
- **THEN** страница отвечает «не найдено», API отвечает 404, чат не меняется

#### Scenario: Без входа
- **WHEN** запрос к API чата приходит без сессии
- **THEN** ответ не содержит данных и ничего не сохраняется

### Requirement: История чатов
Боковая панель SHALL показывать чаты пользователя, новые сверху, в группах «Закреплённые», «Сегодня», «Вчера», по дате для последней недели, «Ранее» и свёрнутой «Архив». Пустые группы MUST не показываться. Панель SHALL содержать «+ Новый чат», поиск по названиям и для каждого чата действия «Закрепить»/«Открепить», «В архив»/«Из архива», «Удалить» (с подтверждением). На широком экране панель SHALL быть по умолчанию скрыта и показываться кнопкой в шапке чата; выбор MUST запоминаться в браузере. На узком экране панель SHALL открываться той же кнопкой поверх ленты.

#### Scenario: Поиск
- **WHEN** пользователь вводит часть названия в поиск
- **THEN** остаются только подходящие чаты, группы без совпадений скрываются

#### Scenario: Закрепление
- **WHEN** пользователь закрепляет чат
- **THEN** чат переходит в группу «Закреплённые» вверху списка

#### Scenario: Архив
- **WHEN** пользователь отправляет чат в архив
- **THEN** чат пропадает из обычных групп и виден только в группе «Архив»

#### Scenario: Удаление открытого чата
- **WHEN** пользователь подтверждает удаление чата, который сейчас открыт
- **THEN** чат удаляется и открывается новый пустой чат

#### Scenario: История скрыта по умолчанию
- **WHEN** пользователь впервые открывает чат на широком экране
- **THEN** панели истории не видно; кнопка в шапке показывает её, и при следующем открытии чата она видна

### Requirement: Название чата
После первого ответа ассистента система SHALL дать чату короткое название, сгенерированное моделью. Если модель не ответила, ответила пусто или слишком длинно, название MUST браться из начала первого сообщения пользователя (не длиннее 60 символов).

#### Scenario: Модель придумала название
- **WHEN** завершился первый ответ в новом чате и модель вернула название
- **THEN** чат в истории показывается под этим названием

#### Scenario: Модель недоступна
- **WHEN** запрос названия к модели завершился ошибкой
- **THEN** названием становится начало первого сообщения пользователя

### Requirement: Выбор модели
Чат — это Ассистент: он SHALL отвечать моделью, выбранной в окне «Ассистент». Выбора модели в самом чате MUST NOT быть. Подмены на другую модель MUST NOT быть. Если своих моделей нет, а модель задана в `.env`, чат SHALL работать на ней без выбора. Если модели нет нигде, чат SHALL показывать предупреждение со ссылкой на «Модели», а отправка MUST быть недоступна.

#### Scenario: Смена модели
- **WHEN** пользователь меняет модель в окне «Ассистент» и отправляет сообщение в любом чате
- **THEN** ответ генерирует новая модель Ассистента; в шапке чата выбора модели нет

#### Scenario: Модель удалили
- **WHEN** пользователь пытается удалить модель Ассистента
- **THEN** удаление не проходит, чат продолжает отвечать этой моделью

#### Scenario: Нет ни одной модели
- **WHEN** в реестре нет моделей и в `.env` модель не задана
- **THEN** вместо ответа видно предупреждение со ссылкой на «Модели», кнопка отправки неактивна

### Requirement: Потоковый ответ
Ответ ассистента SHALL появляться по мере генерации. Пока ответ идёт, кнопка отправки MUST превращаться в «Остановить»; остановка прерывает генерацию и оставляет уже полученный текст. Ошибка модели SHALL показываться в ленте понятным текстом, в котором нет токена модели. Enter SHALL отправлять сообщение, Shift+Enter — переносить строку.

#### Scenario: Остановка
- **WHEN** пользователь нажимает «Остановить» во время ответа
- **THEN** генерация прекращается, полученная часть ответа остаётся, поле ввода снова доступно

#### Scenario: Ошибка модели
- **WHEN** сервер модели отвечает ошибкой
- **THEN** в ленте видно сообщение об ошибке и кнопка «Повторить», введённое сообщение не теряется

### Requirement: Действия над сообщениями
Под ответом ассистента SHALL быть «Копировать», а под последним ответом — ещё «Повторить». Под сообщением пользователя SHALL быть «Копировать» и «Изменить». «Изменить» MUST открывать правку текста на месте; сохранение отбрасывает все сообщения после изменённого и отправляет его заново.

#### Scenario: Повторить
- **WHEN** пользователь нажимает «Повторить» под последним ответом
- **THEN** последний ответ заменяется новым, история сохраняется уже с ним

#### Scenario: Изменить
- **WHEN** пользователь правит своё сообщение из середины чата и сохраняет
- **THEN** сообщения после него удаляются, ассистент отвечает на исправленный текст

#### Scenario: Копировать
- **WHEN** пользователь нажимает «Копировать»
- **THEN** текст сообщения попадает в буфер обмена и появляется уведомление «Скопировано»

### Requirement: Инструменты ассистента
Ассистент SHALL иметь только инструменты, разрешённые в его настройках: «Запустить агента» — запуск одного из разрешённых и включённых агентов пользователя — и, если ассистенту добавлен включённый почтовый коннектор, почтовые инструменты, включённые на вкладке «Инструменты» этого коннектора и доступные по его подключению (см. `mail-tools`). Всегда доступны «Дата и время» (`current_time`) и «Политики» (`get_policies`: HITL и гардрейлы ассистента, тексты включённых документов, модель и коннекторы с тем, что они дают, словами). Перед каждым ответом сервер MUST сам добавлять в историю модели вызов «Политики» с результатом. Инструкция ассистента SHALL быть постоянной: правила ответа, работы с инструментами и с политиками, без их содержимого; письма менять и отправлять — только по просьбе пользователя. Инструмента «Траты» у ассистента MUST NOT быть; прежние вызовы в сохранённых чатах SHALL отображаться как раньше.

Инструменты MUST работать только с данными текущего пользователя. Каждый вызов SHALL отображаться в ленте строкой-сводкой, которая раскрывается в подробности (параметры и результат или журнал прогона).

#### Scenario: Вопрос о тратах
- **WHEN** пользователь спрашивает, сколько потрачено за месяц
- **THEN** инструмент «Траты» не вызывается, ассистент цифр не выдумывает

#### Scenario: Нет агентов
- **WHEN** у пользователя нет разрешённых включённых агентов
- **THEN** инструмент «Запустить агента» ассистенту не предлагается

#### Scenario: Траты не разрешены
- **WHEN** открыт сохранённый чат, где ассистент раньше вызывал «Траты»
- **THEN** строка вызова «Траты» видна в ленте, чат продолжается без ошибок

#### Scenario: Разбор почты по запросу
- **WHEN** у ассистента есть включённый почтовый коннектор и пользователь спрашивает «что пришло за сегодня?»
- **THEN** в ленте появляется строка с числом найденных писем, а ответ опирается на найденные письма

#### Scenario: Почта не добавлена
- **WHEN** почтового коннектора у ассистента нет или он выключен, и пользователь просит разобрать почту
- **THEN** почтовые инструменты не вызываются, ассистент говорит, что это можно разрешить в «Агенты → Ассистент»

#### Scenario: Инструмент снят
- **WHEN** у коннектора снята галочка «Отправлять письма» и пользователь просит отправить письмо
- **THEN** модели этот инструмент не предлагается, ассистент говорит, что отправка не разрешена

#### Scenario: Политики всегда у модели
- **WHEN** у ассистента документ «Регламент» и пользователь задаёт вопрос
- **THEN** модель получает в истории результат «Политики» с текстом «Регламента», а в инструкции его текста нет

#### Scenario: Дата
- **WHEN** пользователь спрашивает «что пришло сегодня?»
- **THEN** модель может узнать дату инструментом «Дата и время»; в инструкции даты нет

### Requirement: Подтверждение действий
Запуск агента с HITL «Подтверждать запуск» (у «Чеков из почты» — всегда) SHALL выполняться только после подтверждения пользователя: в ленте появляется карточка «⏸ Нужно подтверждение» с названием агента и кнопками «Запустить» и «Отмена». После прогона в ленте SHALL быть итог прогона и, если появились новые чеки, кнопка «Открыть «Траты»».

Почтовые изменения и отправка Ассистента SHALL подтверждаться по его HITL: «Спрашивать перед изменением и отправкой» — и изменения, и отправка; «Спрашивать только перед отправкой» — только отправка; «Не спрашивать» — ничего. Карточка «⏸ Нужно подтверждение» называет действие и что именно будет сделано (кому, тема, сколько писем, куда), кнопки «Выполнить» и «Отмена». Подтверждение MUST проверяться на сервере: подделанное клиентом подтверждение не запускает ни агента, ни действие с почтой. Отказ записывается в журнал.

#### Scenario: Подтверждение
- **WHEN** ассистент хочет запустить агента и пользователь нажимает «Запустить»
- **THEN** агент выполняется, прогон записывается в его историю, ассистент сообщает итог

#### Scenario: Отказ
- **WHEN** пользователь нажимает «Отмена»
- **THEN** агент не запускается, в ленте видно «Запуск отменён», ассистент продолжает без него

#### Scenario: Ошибка прогона
- **WHEN** прогон агента завершился ошибкой (например, не настроена почта)
- **THEN** строка вызова показывает ошибку и журнал, ассистент объясняет, чего не хватает

#### Scenario: Задача агенту
- **WHEN** ассистент запускает «Своего агента»
- **THEN** он передаёт агенту задачу текстом, а ответ агента виден в строке прогона и в ответе ассистента

#### Scenario: Отправка с подтверждением
- **WHEN** HITL Ассистента «Спрашивать только перед отправкой» и он отвечает на письмо
- **THEN** в ленте карточка с адресатом и темой; письмо уходит только после «Выполнить»

#### Scenario: Изменение без вопроса
- **WHEN** HITL Ассистента «Спрашивать только перед отправкой» и он перемещает письма в «Архив»
- **THEN** письма перемещаются без карточки, в ленте строка «Перемещено N писем в «Архив»»

### Requirement: Вход ведёт в последний чат
После входа система SHALL открывать последний изменённый чат пользователя, не считая архивных. Если таких чатов нет, MUST открываться новый чат.

#### Scenario: Есть чаты
- **WHEN** пользователь с несколькими чатами входит в портал
- **THEN** открывается `/chat/<id>` чата, в котором было последнее сообщение

#### Scenario: Последний чат в архиве
- **WHEN** самый свежий чат пользователя отправлен в архив
- **THEN** открывается самый свежий из неархивных чатов

#### Scenario: Чатов нет
- **WHEN** у пользователя ещё нет чатов
- **THEN** открывается новый чат «Чем помочь?»

### Requirement: Краткие результаты инструментов
Модель SHALL получать результаты инструментов из сообщений до текущего вопроса в кратком виде: у найденных писем — без начала текста, у прочитанного письма — не больше 300 символов текста, у запуска агента — без журнала. Сохранённая история MUST NOT меняться.

#### Scenario: Старые письма короче
- **WHEN** пользователь нашёл письма, а потом задал следующий вопрос
- **THEN** модель получает у прошлых писем id, дату, отправителя и тему, без начала текста

### Requirement: Пересказ начала чата
Когда оценка объёма истории для модели больше 70 % поля «Контекст, токенов» её модели, начало чата (кроме текущего вопроса) SHALL сжиматься этой моделью в пересказ, который хранится у чата и передаётся модели вместо пересказанных сообщений. Пересказ MUST сбрасываться, если пересказанная часть изменилась. Ошибка пересказа MUST NOT мешать ответу. В чате SHALL быть линия «Выше — пересказано для модели»; в журнал пишется «История чата сжата».

#### Scenario: Пересказ
- **WHEN** история чата больше 70 % контекста модели
- **THEN** начало чата заменяется для модели пересказом, ответ приходит, в чате видна линия «Выше — пересказано для модели»

#### Scenario: Правка пересказанного
- **WHEN** пользователь изменил сообщение из пересказанной части
- **THEN** пересказ сбрасывается, модель снова получает историю с начала
