# llm-models Specification

## Purpose
Реестр LLM-моделей портала: какие OpenAI-совместимые модели подключены, какая из них по умолчанию, какой моделью работает каждый агент и как безопасно хранится токен доступа.

## Requirements

### Requirement: Таблица моделей
Страница `/models` SHALL показывать таблицу моделей: ID, Название (у модели по умолчанию — пометка «по умолчанию»), Модель (идентификатор модели, например `gpt-oss:120b`), Агенты (сколько агентов работает на модели, включая тех, кто на «по умолчанию»), Статус (результат последней проверки: «подключена», «ошибка» или «не проверена»). Есть поиск и вкладки раздела AI.

#### Scenario: Две модели
- **WHEN** подключены GLM-4 (по умолчанию) и Llama 3.1
- **THEN** в таблице две строки, у GLM-4 пометка «по умолчанию»

#### Scenario: Моделей нет, но задан .env
- **WHEN** в реестре нет моделей, а в `.env` заданы `LLM_BASE_URL` и `LLM_MODEL`
- **THEN** над таблицей видно, что сейчас используется модель из `.env` (имя модели без токена)

#### Scenario: Колонка «Модель»
- **WHEN** в реестре модель «Ollama Cloud» с идентификатором `gpt-oss:120b`
- **THEN** в её строке в колонке «Модель» написано `gpt-oss:120b`, а адреса API в таблице нет

### Requirement: Свои модели у каждого
Каждая модель SHALL принадлежать пользователю. Страница «Модели» SHALL показывать только свои модели, и любой пользователь SHALL добавлять, изменять, проверять и удалять свои модели. Чужие модели MUST NOT показываться, а запросы к ним сервер MUST отклонять. Модель по умолчанию — своя у каждого; первая своя модель становится моделью по умолчанию. Модели, у которых не было владельца, SHALL переходить к первому администратору.

#### Scenario: Обычный пользователь
- **WHEN** пользователь без роли администратора открывает `/models`
- **THEN** он видит только свои модели и может добавлять и менять их

#### Scenario: Чужая модель
- **WHEN** пользователь пытается выбрать для агента или изменить модель другого пользователя
- **THEN** сервер отвечает «Такой модели нет», ничего не меняется

### Requirement: Добавление и изменение модели
Кнопка «+ Добавить модель» и иконка «Изменить» SHALL открывать модалку с полями Название, Адрес API (обязательно, http/https), Модель (обязательно), Токен (скрытый ввод с кнопкой показа), Контекст, токенов (2 000–2 000 000, по умолчанию 32 000), «Сделать моделью по умолчанию».
- Пустое название заменяется идентификатором модели.
- Первая добавленная модель автоматически становится моделью по умолчанию.
- «Контекст, токенов» — сколько модель держит в памяти; по нему чат решает, когда пересказывать начало.

#### Scenario: Добавить
- **WHEN** администратор заполняет адрес `http://localhost:11434/v1` и модель `llama3.1` и нажимает «Сохранить»
- **THEN** модалка закрывается, появляется «Модель добавлена», в таблице новая строка

#### Scenario: Некорректный адрес
- **WHEN** в «Адрес API» введено `localhost:11434`
- **THEN** модалка показывает ошибку «Адрес должен начинаться с http:// или https://»

#### Scenario: Контекст
- **WHEN** пользователь указывает «Контекст, токенов» 8000 и сохраняет
- **THEN** при следующем открытии в поле 8000

### Requirement: Защита токена
Токен SHALL храниться в базе только в зашифрованном виде и MUST NOT отдаваться в браузер, писаться в логи и показываться в интерфейсе. При изменении модели поле токена пустое с подсказкой «Токен сохранён — оставьте пустым, чтобы не менять». Пустое значение сохраняет прежний токен, новое значение заменяет его. Отдельной отметки для удаления токена нет.

#### Scenario: Правка без токена
- **WHEN** администратор меняет название модели, не трогая поле токена
- **THEN** прежний токен остаётся и используется в запросах

#### Scenario: Страница без токенов
- **WHEN** открыта страница `/models`
- **THEN** в HTML страницы нет ни одного сохранённого токена

#### Scenario: Замена токена
- **WHEN** администратор вводит в поле токена новое значение и сохраняет модель
- **THEN** в запросах используется новый токен, прежний больше не хранится

### Requirement: Модель по умолчанию
Ровно одна модель SHALL быть моделью по умолчанию, если в реестре есть хотя бы одна модель. Переключатель «Сделать моделью по умолчанию» снимает этот признак с прежней; у самой модели по умолчанию он включён и заблокирован. Если у пользователя ещё нет моделей, в окне новой модели переключатель MUST быть включён и заблокирован с пояснением, что первая модель всегда становится моделью по умолчанию. В списках выбора модели (окно агента, ассистента) подписи «по умолчанию» нет — модель по умолчанию просто выбрана у нового агента.

#### Scenario: Сменить модель по умолчанию
- **WHEN** администратор включает «Сделать моделью по умолчанию» у Llama и сохраняет
- **THEN** пометка «по умолчанию» переходит с GLM-4 на Llama

#### Scenario: Первая модель
- **WHEN** у пользователя нет моделей и он открывает «Добавить модель»
- **THEN** «Сделать моделью по умолчанию» включён, изменить его нельзя, видно «Это первая модель — она всегда становится моделью по умолчанию»

### Requirement: Проверка подключения
Кнопка «Проверить» в модалке SHALL отправлять пробный запрос `chat/completions` по введённым (ещё не сохранённым) данным и показывать «✓ Модель ответила — N мс» или ошибку. Иконка «Проверить» в строке проверяет сохранённую модель и обновляет её статус. Ожидание ответа ограничено 20 секундами.

#### Scenario: Сервер недоступен
- **WHEN** по адресу модели никто не отвечает
- **THEN** показывается «✕ Не удалось подключиться», статус в таблице — «ошибка»

### Requirement: Удаление модели
Иконка «Удалить» SHALL после подтверждения удалять любую модель, в том числе модель по умолчанию. Агенты и чат, работавшие на удалённой модели, переходят на модель по умолчанию; если удалена модель по умолчанию, ею становится самая ранняя из оставшихся (окно подтверждения об этом предупреждает). Без моделей чат и агенты показывают, что модель нужно добавить.

#### Scenario: Удалить модель агента
- **WHEN** удалена модель, выбранная у агента «Сводка почты»
- **THEN** агент работает на модели по умолчанию

#### Scenario: Удалить модель по умолчанию
- **WHEN** удалена модель по умолчанию, а в реестре есть ещё модели
- **THEN** моделью по умолчанию становится самая ранняя из оставшихся

### Requirement: Модель агента
На странице агента SHALL быть выбор «Модель»: «По умолчанию» или одна из моделей реестра. Выбранная модель используется при прогонах агента.

#### Scenario: Своя модель
- **WHEN** у агента выбрана Llama 3.1
- **THEN** прогоны агента отправляют запросы на адрес и модель Llama 3.1

### Requirement: Порядок выбора модели
При вызове LLM портал SHALL использовать модель агента (или ассистента), если она задана и принадлежит тому же пользователю. Иначе — модель по умолчанию этого пользователя. Иначе — `LLM_BASE_URL` / `LLM_MODEL` / `LLM_API_KEY` из `.env`. Если не задано ничего, вызов MUST завершаться понятной ошибкой «LLM не настроена».

#### Scenario: Старая установка
- **WHEN** реестр пуст, а `.env` заполнен как раньше
- **THEN** агенты работают на модели из `.env`
