# audit-log Specification

## Purpose
Журнал событий портала: что, кто, когда и откуда сделал — для администратора.

## Requirements

### Requirement: Запись событий
Система SHALL записывать в журнал время, автора (пользователя или «Систему»), тип события, канал (портал, чат, система) и детали для входа и выхода, действий с пользователями и доступами, моделями, агентами (включая запуск с итогом), чатами (включая подтверждение запуска агента и вызов «Трат») и для прохождения уроков и тестов.

#### Scenario: Вход
- **WHEN** пользователь входит в портал
- **THEN** в журнале появляется запись «вход» с его именем и деталями «Вход в систему»

#### Scenario: Неудачный вход
- **WHEN** кто-то вводит неверный пароль
- **THEN** в журнале появляется запись «неудачный вход» с указанным e-mail, без пароля

#### Scenario: Запуск агента из чата
- **WHEN** пользователь подтверждает в чате запуск агента и прогон завершается
- **THEN** в журнале есть запись о подтверждении и запись о запуске с каналом «чат» и итогом прогона

### Requirement: Без секретов и без сбоев
Журнал MUST NOT содержать паролей, токенов и текста сообщений чата. Ошибка записи в журнал MUST NOT прерывать основное действие.

#### Scenario: Токен модели
- **WHEN** администратор сохраняет модель с токеном
- **THEN** запись «модель» содержит название и адрес, но не токен

### Requirement: Страница «Журнал»
Страница `/admin/log` SHALL быть доступна только администратору и показывать заголовок «Журнал» с общим числом записей, поиск «Поиск по пользователю или событию…», кнопку «+ Фильтр» с отметками по событиям и каналам и таблицу с колонками Дата, Пользователь, Событие, Канал, Детали, новые записи сверху. Событие SHALL показываться цветной меткой. Записи MUST выводиться страницами по 50 с переключателем страниц. Поиск SHALL не зависеть от регистра, в том числе для русских букв.

#### Scenario: Поиск
- **WHEN** администратор вводит в поиск часть имени пользователя
- **THEN** остаются только записи этого пользователя, число записей в заголовке обновляется

#### Scenario: Фильтр по событию
- **WHEN** администратор отмечает в фильтре событие «вход»
- **THEN** в таблице остаются только входы, на кнопке видно «Фильтр · 1»

#### Scenario: Страницы
- **WHEN** записей больше 50
- **THEN** под таблицей есть переключатель страниц, вторая страница показывает следующие 50 записей

#### Scenario: Не администратор
- **WHEN** пользователь без роли администратора открывает `/admin/log`
- **THEN** его перенаправляет на главную, журнал не показывается
